Обзор

Программа решает головоломку 8-puzzle конкурентно: стартовое состояние превращается в дерево возможных ходов, а каждый новый узел отправляется в пул потоков как отдельная задача. Как только найдено целевое состояние, результат публикуется и восстанавливается путь ходов.

Архитектура

  • Main запускает демонстрационный сценарий.
  • ConcurrentPuzzleSolver управляет параллельным поиском.
  • SlidingPuzzle задаёт правила конкретной головоломки.
  • BoardPosition хранит неизменяемое состояние доски.
  • ValueLatch хранит первое найденное решение.

Ключевая мысль

Этот пример показывает не оптимизацию самого пазла, а паттерн: конкурентный обход дерева состояний с защитой от повторного посещения и единичной публикацией ответа.

Классы и ответственность

Класс За что отвечает Что важно понять
org.example.Main Точка входа и демонстрация результата. Создаёт стартовую позицию, запускает решатель, печатает путь и промежуточные состояния.
org.example.puzzle.ConcurrentPuzzleSolver Оркестрация конкурентного поиска. Раздаёт узлы в ExecutorService, отсеивает повторы и ждёт первую найденную цель.
org.example.puzzle.Puzzle Контракт для любой головоломки. Набор операций: старт, проверка цели, допустимые ходы и применение хода.
org.example.puzzle.SlidingPuzzle Правила 8-puzzle. Определяет валидные направления и проверяет, собрана ли доска.
org.example.puzzle.BoardPosition Неизменяемая конфигурация доски. Хранит плитки, ищет пустую клетку и создаёт новое состояние после обмена плиток.
org.example.puzzle.Direction Перечисление ходов. Содержит смещения по строкам и столбцам для каждого направления.
org.example.puzzle.PuzzleNode Узел дерева поиска. Хранит текущую позицию, родителя и последний ход для восстановления пути.
org.example.puzzle.ValueLatch Однократная фиксация ответа. Один раз публикует найденный узел и будит ожидающие потоки.

Поток выполнения

1. Подготовка `Main` собирает стартовое состояние и создаёт пул потоков.
2. Старт поиска `ConcurrentPuzzleSolver.solve()` кладёт начальный узел в пул задач.
3. Расширение узлов Каждая задача проверяет позицию, затем генерирует дочерние состояния по допустимым ходам.
4. Отсечение повторов Повторно увиденные позиции не обрабатываются повторно.
5. Публикация результата Как только достигнута цель, найденный узел сохраняется и путь восстанавливается через родителей.

Ограничения

  • Нет проверки, что стартовая конфигурация вообще решаема.
  • Пример не пытается гарантировать кратчайший путь.
  • Решение ориентировано на демонстрацию параллельного подхода, а не на масштабирование.
