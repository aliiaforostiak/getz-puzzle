Конкурентный решатель головоломки

Этот пример показывает, как параллельно исследовать дерево состояний головоломки, находить первое решение и восстанавливать последовательность ходов. Код реализует упрощённый вариант идеи из книги Гетца: каждая новая позиция рассматривается как отдельная задача в пуле потоков.

Что делает программа

  • Main создаёт стартовую конфигурацию 8-puzzle.
  • SlidingPuzzle знает правила игры: какие ходы разрешены и когда достигнута цель.
  • ConcurrentPuzzleSolver запускает параллельный поиск решения.
  • Когда цель найдена, программа печатает список ходов и пошагово показывает результат.

Ключевая идея

Вместо последовательного обхода всех состояний каждое возможное продолжение позиции отправляется в ExecutorService как отдельная задача. Повторно посещённые состояния отсекаются через конкурентную карту, поэтому один и тот же узел не исследуется дважды.

Классы и ответственность

Класс Ответственность Что важно аналитику
org.example.Main Точка входа и демонстрационный сценарий. Создаёт стартовую доску, запускает решатель, выводит решение и промежуточные состояния.
org.example.puzzle.ConcurrentPuzzleSolver Оркестрирует конкурентный поиск. Делает первую задачу из стартовой позиции, раздаёт дочерние позиции в пул и ждёт первое найденное решение.
org.example.puzzle.Puzzle Контракт для любой головоломки. Определяет старт, проверку цели, генерацию ходов и применение хода к позиции.
org.example.puzzle.SlidingPuzzle Правила 8-puzzle. Знает, где находятся допустимые направления движения и как выглядит целевая конфигурация.
org.example.puzzle.BoardPosition Неизменяемое состояние доски. Хранит размер и список плиток, умеет находить пустую клетку и менять две плитки местами.
org.example.puzzle.Direction Перечисление ходов. Четыре направления: вверх, вниз, влево, вправо. Каждое хранит смещение по строкам и столбцам.
org.example.puzzle.PuzzleNode Узел дерева поиска. Хранит текущую позицию, ссылку на родителя и последний ход для восстановления пути к решению.
org.example.puzzle.ValueLatch Однократная публикация результата. Один поток записывает найденное решение, остальные ждут и затем получают итоговую позицию.

Поток выполнения

1. Инициализация `Main` создаёт стартовую позицию и пул потоков.
2. Запуск решения `ConcurrentPuzzleSolver.solve()` кладёт стартовый узел в пул как первую задачу.
3. Параллельный обход Каждый узел проверяется на цель, затем порождает дочерние позиции через допустимые ходы.
4. Отсечение повторов Если позиция уже встречалась, она не исследуется повторно.
5. Публикация ответа При достижении цели узел сохраняется в `ValueLatch`, после чего путь собирается назад по родителям.

Как читать код

  • Сначала смотреть на Main, если нужен сценарий запуска.
  • Затем ConcurrentPuzzleSolver, если нужно понять конкурентную механику.
  • Потом SlidingPuzzle и BoardPosition, если нужны правила и данные.
  • ValueLatch важен для понимания того, как фиксируется единственный результат.

Ограничения примера

  • Не выполняется проверка на решаемость конфигурации.
  • Не гарантируется поиск кратчайшего решения, если несколько веток найдут цель одновременно.
  • Пример рассчитан на демонстрацию подхода, а не на оптимизацию для больших досок.
