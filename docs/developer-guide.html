Как устроено решение

Конкурентный поиск Параллельные задачи Неизменяемые состояния

Система работает как поисковик по дереву состояний. Каждая позиция головоломки рассматривается как отдельный узел. Из узла генерируются следующие допустимые ходы, а каждый новый ход может быть запущен в другом потоке.

Чтобы не зациклиться, уже увиденные позиции хранятся в конкурентной карте. Чтобы не потерять решение, найденный узел один раз публикуется через ValueLatch. Затем путь восстанавливается обратным проходом по родителям узлов.

`Main`

Метод Что делает На что смотреть
main(String[] args) Создаёт стартовую конфигурацию, запускает решатель, печатает найденный путь. Это демонстрационный сценарий. В реальном приложении сюда можно подставить ввод пользователя или чтение из файла.

Пошагово

  • Создаётся объект BoardPosition со стартовым состоянием.
  • Из него собирается SlidingPuzzle, который знает правила игры.
  • Создаётся пул потоков через Executors.newFixedThreadPool.
  • ConcurrentPuzzleSolver.solve() возвращает список ходов.
  • После этого код печатает старт, решение и промежуточные состояния.

Типичные ошибки

  • Забыть закрыть executor в finally.
  • Передать некорректную стартовую доску без пустой клетки.
  • Не обработать InterruptedException.

`ConcurrentPuzzleSolver`

Элемент Роль Подробности
ConcurrentPuzzleSolver(Puzzle, ExecutorService) Конструктор зависимостей. Получает правило игры и пул потоков. Сам решатель не создаёт executor внутри себя, это делает вызывающий код.
solve() Запускает поиск и ждёт результат. Стартует с начальной позиции, ждёт публикацию найденного узла и возвращает список ходов от старта до цели.

Как работает solve()

  1. Создаётся ValueLatch для первого найденного решения.
  2. Создаётся ConcurrentHashMap для запоминания уже посещённых позиций.
  3. В пул отправляется первый узел с начальной позицией.
  4. Метод ждёт, пока какой-то поток не положит решение в latch.
  5. Когда решение найдено, путь берётся через PuzzleNode.asMoveList().

Как работает newTask(...)

Это приватная фабрика задач. Она создаёт Runnable, который умеет проверить состояние, отбросить дубликаты, определить цель и запустить дочерние состояния.

  • Сначала задача проверяет, не найдено ли решение раньше.
  • Потом пробует добавить текущую позицию в seen.
  • Если позиция уже была, задача завершается сразу.
  • Если позиция целевая, текущий узел публикуется в ValueLatch.
  • Иначе задача генерирует дочерние узлы и отправляет их в executor.

Важный контракт

Узлы должны быть неизменяемыми по смыслу. Если позиция будет меняться после помещения в seen, поиск начнёт вести себя непредсказуемо.

`Puzzle`

Метод Контракт Что реализует конкретная игра
initialPosition() Возвращает начальное состояние. Для 8-puzzle это стартовая доска.
isGoal(P) Проверяет, является ли позиция конечной. Для 8-puzzle все плитки должны стоять по порядку, а пустая клетка быть последней.
legalMoves(P) Возвращает допустимые ходы из позиции. Для 8-puzzle это направления, куда можно сдвинуть пустую клетку.
move(P, M) Возвращает новую позицию после применения хода. Для 8-puzzle это обмен пустой клетки с соседней плиткой.

Зачем нужен интерфейс

  • Позволяет переиспользовать конкурентный решатель для разных игр.
  • Отделяет алгоритм поиска от правил конкретной головоломки.
  • Упрощает тестирование: можно подставить небольшой искусственный puzzle.

`SlidingPuzzle`

Метод Что делает Подводные камни
SlidingPuzzle(BoardPosition) Сохраняет стартовую позицию. Должна быть валидная доска, иначе дальнейшие методы могут упасть.
initialPosition() Возвращает стартовую доску. Используется решателем как корень поиска.
isGoal(BoardPosition) Проверяет, собрана ли головоломка. Логика жёстко завязана на правильный порядок плиток для 3x3 доски.
legalMoves(BoardPosition) Возвращает направления, доступные пустой клетке. Нужно учитывать границы поля, иначе ход станет недопустимым.
move(BoardPosition, Direction) Строит новое состояние после хода. Метод не меняет входной объект, а создаёт новый.

Пример использования

BoardPosition start = new BoardPosition(3, List.of(
    1, 2, 3,
    4, 5, 6,
    0, 7, 8
));
SlidingPuzzle puzzle = new SlidingPuzzle(start);
List<Direction> moves = puzzle.legalMoves(start);

`BoardPosition`

Метод Назначение
BoardPosition(int, List<Integer>) Создаёт позицию доски и валидирует размер.
size() Возвращает размер стороны доски.
tiles() Возвращает список плиток в виде неизменяемой копии.
blankIndex() Ищет индекс пустой клетки 0.
swap(int, int) Создаёт новое состояние с обменёнными плитками.
equals / hashCode Позволяют использовать позицию как ключ в карте посещённых состояний.
toString() Печатает доску в читаемом виде.

Почему класс неизменяемый

  • Так безопаснее использовать его в нескольких потоках.
  • Объекты можно хранить в ConcurrentHashMap без риска изменения ключа.
  • Каждый ход создаёт новое состояние, а не ломает старое.

`Direction`

Элемент Что означает
UP Сдвиг пустой клетки вверх.
DOWN Сдвиг пустой клетки вниз.
LEFT Сдвиг пустой клетки влево.
RIGHT Сдвиг пустой клетки вправо.
rowDelta() Смещение по строкам.
columnDelta() Смещение по столбцам.

Как использовать

`Direction` нужен как типобезопасная замена строкам или числам. Это исключает ошибки, когда кто-то передаёт невалидное направление.

`PuzzleNode`

Поле / метод Роль
parent Ссылка на предыдущий узел в дереве поиска.
move Последний ход, который привёл в текущую позицию.
position() Возвращает текущую позицию узла.
asMoveList() Восстанавливает путь от корня до текущего узла.

Почему это важно

Решатель хранит не только конечную позицию, но и цепочку родителей. Без этого нельзя вернуть пользователю сам путь решения, только факт, что цель найдена.

`ValueLatch`

Метод Что делает
isSet() Проверяет, было ли уже опубликовано значение.
setValue(T) Пробует записать значение один раз и разблокировать ожидание.
getValue() Ждёт, пока значение не будет установлено, и возвращает его.

Смысл класса

  • Это синхронизационный объект для сценария "найти первое решение".
  • Он не хранит несколько ответов, только один.
  • Он отделяет момент нахождения решения от момента, когда вызывающий код его получит.

Как расширять проект

Добавить новую головоломку

  • Создать новый класс, который реализует Puzzle<P, M>.
  • Определить свой тип позиции P и свой тип хода M.
  • Передать новую реализацию в ConcurrentPuzzleSolver.

Сделать ввод гибким

  • Вынести стартовую позицию из Main в параметры запуска.
  • Добавить парсинг из файла или строки.
  • При необходимости показать несколько стартовых конфигураций для сравнения.

Что проверять при изменениях

  • Не ломается ли equals/hashCode у позиций.
  • Не меняются ли объекты позиции после помещения в карту посещённых состояний.
  • Корректно ли закрывается executor после завершения.
  • Возвращается ли пустой список, если старт уже является целью.
